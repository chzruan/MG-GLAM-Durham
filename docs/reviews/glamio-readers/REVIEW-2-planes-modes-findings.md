## 1. Summary

The three readers reproduce the Fortran layouts, units and epochs exactly:
the lens planes match an independent projection of the CIC density for all
three axes and every slab (the transposed alternative is off by O(1)); the
mode cubes equal the `exp(-i k.x)/N^3` FFT of the CIC density and of the
momentum deposit to float32 precision (the conjugate and the x<->y swap are
off by 8-13 rms), so the sign convention, the Hermitian completion and the
axis order are right; `power()` equals `PowerDM.R` bin by bin for a
structural reason (one packed entry per full-sphere mode, `iCIC = 0` is a
compile-time constant, all modes of bins `b <= n <= N/2-1` lie inside the
cube), not by small-`n` coincidence; the fR_halo pairs are one per written
catalogue row and the catalogue join works for both formats. No Blocker.
Three Majors: `power()` needs ~4.7 GB and ~12 s for the production cube
(k_c = 1.5, Box = 1024), `power(nbins > n)` silently returns partial-shell
averages 5-19 % low, and `load_array(mmap=True)` crashes on an empty product
(`rows = 0`). Recommendation: **ready after the listed fixes** (M1-M3 and the
docstring fix m1 are each a few lines).

## 3. Verified OK

- **Byte order and record structure.** `LensPlanes` (extras.f90:115), `DumpModes` (:382) and `fRHaloOpen` (:575) all open with `access='stream', form='unformatted', convert='little_endian'`, so the build's `-convert big_endian` (makefile:6) does not apply and there are no record markers; the readers use explicit `"<f4"`, `"<c8"` and `FRHALO_DTYPE = [("fR_centre","<f4"),("fR_mean","<f4")]`; `check_size` demands the exact byte count (`4*3*N_slab*N_lens^2`, `8*(2n+1)^2(n+1)`, `8*rows`).
- **Lens-plane orientation, all axes.** From the loops (extras.f90:120-161): X planes `acc(ip<-iy, jp<-iz, s)`, Y planes `(ip<-ix, jp<-iz)`, Z planes `(ip<-ix, jp<-iy)`; `write (29) plane` streams `i` fastest; the reader's `reshape(3 N_slab, N_lens, N_lens)` is `[plane, j, i]` and `plane(axis, s)` returns `.T = [i, j]`. Numerically on case10 steps 70/84/98 (72^3 mesh, 2 slabs): `plane(ax, s)` equals my projection of an independent DENSIT-style CIC of `PMcrs0` (mean of `1+delta` over the slab's `nc` cells, then `f x f` block mean) for all three axes and both slabs to <= 2e-6 (float32); the transposed alternative differs by 2.2-9.1. Plane order X1..XN, Y1..YN, Z1..ZN (`iax` outer, `s` inner, extras.f90:117/164): `slabs('x')` is a view of `planes[0:N_slab]`, `plane('z', N_slab)` is `planes[3 N_slab - 1].T`. `slab` is 1-based as in the sidecar, `plane('x', 0)` raises `IndexError`.
- **Pixel and slab conventions.** Slab `s` = cells `(s-1) nc + 1 .. s nc`, pixel `ip` = nodes `(ip-1) f + 1 .. ip f`, node `i` at `(i-1) Box/NGRID`, so pixel `(i, j)` covers `[(i-1), i) Box/N_lens` and slab `s` covers `[(s-1), s) depth` exactly as the sidecar says; `pixel_edges() = linspace(0, Box, N_lens+1)` and `slab_edges() = linspace(0, Box, N_slab+1)` match (2.0833 Mpc/h pixels and 75 Mpc/h slabs on case10; 0.5 Mpc/h and 256 Mpc/h on the pilot). `depth` uses the sidecar key when present, else `Box/N_slab`.
- **Plane values.** `plane = 1 + acc*wnorm`, `wnorm = 1/(nc f^2)`, so each axis mean is `1 + <delta>_mesh`; DENSIT sets `FI = -1` and deposits `Wpar = NGRID^3/Nparticles` per particle (density.f90:39-41, 264-279), so `<delta>_mesh = 0` up to rounding: `axis_means() - 1` is 3e-10 to 6e-10 on case10 and 1e-12 to 1e-11 on the pilot. Reading the pilot with `mmap=True` keeps `planes`, `slabs()` and `plane()` as `np.memmap`; `axis_means()` over the 201 MB file took 0.1 s and the whole script peaked at 571 MB RSS.
- **`N_lens` handling.** The Fortran always writes the resolved value (`Nl = NGRID` when `LensGrid <= 0`, extras.f90:105-106, 205) and `N_planes = 3 Ns`; the reader requires `N_slab`, `N_lens`, `Box`, cross-checks `N_planes` when present, and fails with a `ValueError` naming the sidecar otherwise. `f = NGRID/N_lens = 1` is what both real data sets exercise; the reader does not depend on `f`.
- **Mode-cube layout and sign convention.** `C(0:nm,-nm:nm,-nm:nm)` with `C(mz, my, mx)`, `write (29) C` streams `mz` fastest, the reader's `reshape(2n+1, 2n+1, n+1)` is `[ix+n, iy+n, iz]`. Numerically on case11 steps 70/84/98: `data` equals `fftn(delta)/N^3` (numpy's `exp(-2 pi i k n/N)`, i.e. `exp(-i k.x)` with node `i` at `(i-1) Box/N`) of my CIC density to 0.8-1.1e-6 of the rms mode amplitude (float32), while the conjugate differs by 11-13 rms and the x<->y swap by 8.5-9.5 rms. This fixes `PackedBasis`'s `w(2) = -0.5 i sign(m)` against FFTPACK5's `r(2m+1) = -(2/N) sum x sin(...)` as the `exp(-i k.x)` convention and confirms `axis_map`. `mode(ix, iy, iz<0) = conj(data[-ix+n, -iy+n, -iz])` is the correct completion (real fields: `deltam` and each momentum component); the `iz = 0` plane is exactly Hermitian (`plane[::-1, ::-1] == conj(plane)` bitwise), `data[n, n, 0] == 0` exactly (`C(0,0,0) = 0`, extras.f90:380).
- **`nm` clamp and Nyquist.** `nm = int(kc Box/2 pi)`, clamped to `N/2 - 1` (extras.f90:355-359); hence `|m| <= N/2 - 1` and `PackedBasis`'s `abs(m) == N/2` branch is unreachable in the dump; the sidecar's `n` is the clamped value, the reader derives `n` from it and from `data.shape[2] - 1` consistently; `k_c` is documented as the requested cut-off. `n = 0` is accepted (one mode).
- **`power()` equals `PowerDM.R` structurally.** `iCIC = 0` is a module constant (power.f90:12), so POWERfft5 always takes the NGP branch `MP = max(INT(RK+0.5), 1)` = `nint(|m|)` (power.f90:399), skips `k = 0` (:375), weights every packed entry `(I,J,K)` by 1 with `AMP = G^2/8` and accumulates `dkk += RK` (:403-411); the packed layout has exactly one entry per full-sphere mode (`m = K/2` with `K = 1 -> 0`, `K = 2,3 -> 1`, ..., `K = N -> N/2`), and for each `(mx,my,mz)` the sum of `G^2/8` over its 2^d entries equals the sum of `|delta_k|^2` over its 2^d sign partners (Parseval of the cos/sin basis with the `sqrt(2)` factors on `p = 1, N`). `power()` averages the same quantity with weight 2 for `iz > 0` and 1 for `iz = 0` (the whole `iz = 0` plane is in the cube), bins `nint(|m|)`, `k_mean` weighted the same way as `kharm = dk/iVolume * 2 pi/Box`; every mode with `nint|m| = b <= n` has components `<= b <= n <= N/2-1`, so bins `1..n` are complete and never touch the Nyquist plane. Half-integer ties are impossible (`|m|^2` is an integer, `(j+1/2)^2` is not). Numerically: `power()` vs `PowerDM.R` bins 1..11 on steps 70/84/98: max |ratio - 1| = 4.1e-6, 2.8e-6, 2.6e-6 (the Fortran's real*4 FFT), `weight` equals the `N` column exactly, `k_mean` equals `k` to 5e-6 (f9.5 print); `power()` vs a full-sphere float64 binning of my FFT over all 72^3 modes: max |ratio - 1| = 1.6e-7, 8.5e-8, 9.2e-8 with identical counts. The suite's own V2 check (asserts.py:469-480) compares the raw cube with `PowerDM.R` with an independent loop (complete bins `1..n-1`, 1e-4); its `chk_modes` (:788-789) compares `power()` with `binned_power`, which is the same formula (not independent; for Review 4).
- **Momentum cubes.** `mom_x/y/z` equal the FFT of the CIC deposit of `VX * vfac`, `vfac = 100 Box/NGRID/a_v * Nd^3/Np`, with coordinates rescaled by `Nd/NGRID` to the `N_dep = 36` mesh (extras.f90:463-474), to <= 1.7e-6 rms-relative on steps 70 and 98 (`a_v` from the sidecar = `AEXPN - ASTEP/2`, extras.f90:533); the deposited field's mean is 0 km/s. The reader applies no factor; its docstring states `(1 + delta) v_i`, `v` in km/s at `a_v`, on the `N_dep` mesh; `n_dep`, `k_c`, `d_code` (`D_code(a)`) read the right keys.
- **deltaL cubes.** `DeltaLDump.h` writes the same cube (`C[ix+n][iy+n][iz]`, iz fastest, lines 86-91), the same normalisation (`fftw_r2c/N^3`, `exp(-i k.x)`, grid value `j` at `j Box/N`, divided by `D(a_ini)`), `k = 0` zeroed (line 107), little-endian complex64, and a sidecar with `product = deltaL`, `n`, `k_c`, `N_mesh`, `N_dep = N_mesh`, `Box` (lines 121-148). `read_modes` requires only `n`, accepts the product line (`expect_product=None`; `expect_product="deltaL"` also works), and `k_fund`/`wavenumbers()`/`power()` work because `Box` is present. The clamp `n <= Nmesh/2 - 1` is the same (lines 63-68).
- **fR_halo pairs and row order.** `fRHaloRow(x, y, z, Rvir)` is called inside the `WriteFiles` row loop after both `cycle`s (box, `Mvir < MassMin`, `aNpart < 20`) and after the text/binary row writes (`PMP2linker.f90:689-730`), once per written row; `fRHaloClose` writes `rows = nfRrows` and warns if it differs from `Nhalo`. The record is `real(fRbg_old*uc, 4), real(fRbg_old*um, 4)` = `(fR_centre, fR_mean)` in that order (extras.f90:631). `fR_centre` is a CIC interpolation of `FI2^(n+1)` at the centre mapped with `X1 = modulo(x NGRID/Box, NGRID) + 1`; `fR_mean` averages the nodes within `r = Rvir NGRID/Box`. `fR_bg(a_old)` recomputed from the sidecar's `fR0`, `n`, `Omega_m`, `Omega_L`, `a_old` agrees with the sidecar to 1e-8; `a - a_old = ASTEP`. On case12 steps 84/98 the readers return 1 and 5 rows, `|fR_centre|/|fR_bg|` = 0.003-0.09 (screened centres), `fR_mean` less screened than the centre.
- **Catalogue join.** `catalogue`/`catalogue_bin` sidecar values are `CATALOGS/CatshortV.<step>.<box>.{DAT,bin}` followed by a comment; `catalogue_paths()` takes the first token and joins it with `dirname(abspath(.bin))`, i.e. the run directory, which is where the Fortran writes both (cwd); `read_catalogue` dispatches `.DAT` to the text reader and `.bin` to the binary reader; `catalogue()` returned 1/5 rows for both `prefer` values and raises `ValueError` on a row-count mismatch and `FileNotFoundError` naming both candidate paths when neither exists (as for a file copied away from its run directory). `rows = 0` with the default `mmap=False` returns an empty `FRHalo` (`np.fromfile(count=0)` -> size 0).
- **`product.py` helpers used here.** `load_meta` checks the first token of `product` (handles trailing comments), reports missing required keys by name; `meta_int` rounds the first token (`N_p = 1073741824` exact); `check_size` accepts a 0-byte file for `rows = 0`; `load_array(mmap=False)` with `count = 0` works.

## 4. Open questions for the author

1. `power(nbins > n)` (R2-M2): raise, or return `nan` beyond `n`? Downstream code that compares with `PowerDM.R` over `1..NGRID/2` would silently take biased values today.
2. `load_array` for empty products (R2-M3): return `np.empty(0)` for `count == 0` regardless of `mmap`? Which other products can be empty in production (`Subsample` with a large `M` on a small box; the binary catalogue at an early class-1 output) and do their readers route through `load_array`?
3. Pixel convention vs mass support: the planes are block means of CIC *node* values; node `i` at `(i-1) Box/NGRID` collects mass from `[(i-1.5), (i-0.5))` cells, so the mass support of pixel `i` is shifted by half an `N_grid` cell relative to the sidecar's "[(i-1), i) Box/N_lens" statement (the same holds along the projection axis for the slabs). This is the writer's convention and the reader reproduces it; should the README/plan say it explicitly for the lensing users, or should the writer use cell-centred coordinates?
4. Given R2-m1, would a `plane_means()` (shape `(3, N_slab)`) next to `axis_means()` be useful? The Fortran log prints exactly those numbers.
5. deltaL cubes: the sidecar carries `D_gen(a_ini)`, `z_ini`, `seed`, `lpt_order`; `Modes.d_code` returns `None` for them. Should the reader expose `D_gen(a_ini)` (or a generic `growth` property) for the `deltam`/`deltaL` cross-correlation, which needs `D_code(a)` from one file and `D_gen(a_ini)` from the other?
6. The `fR_mean` fallback (R2-n3) is also mis-stated in the Fortran sidecar line (extras.f90:652); fix both, or only the reader's docstring?
7. `index_grids()` is public; if it becomes sparse (R2-m4), does anything downstream rely on dense cube-shaped arrays?
