# REVIEW 1: Fortran writer, config parser and staged publication

Branch `bdm-binary-catalogue` (commit 167fb1c) against `cz`. Scope: the diff of
`PMP2linker.f90` and `PMP2mod_extras.f90` plus the unchanged callers
(`BDM`, `RescaleCoords`, `SetParameters`, `GetHalo`, the Tools module, the
`Analysis` call site, the PM main loop, `makefile`). Read-only review of the
main checkout on 2026-10-18; nothing was built or run. Line numbers refer to
the branch checkout.

## 1. Summary

The binary record layout, the parser branch, the three-file staged publication
and the sidecar's epoch/cosmology values are correct and consistent with the
text catalogue and with the fR_halo/lens-plane writers. One Blocker: the new
`30 format(10x,a,T20,' = ',a,T40,a)` is used for the 15-character key
`CatalogueFormat`, and the leftward `T20` makes the data items overwrite the
tail of the key, so the default `BDM.config` the code writes when none exists
reads `Catalogue = both`; the next `ReadParameters` call (second catalogue
output of the same run, or any restart) rejects it as an unrecognized
parameter and the run dies. Two Majors: the sidecar's `centre = ...` line
misdescribes `Rvir` (it is the SO radius plus the Rext resolution correction,
not the overdensity radius) and `Mbound` (bound mass inside the unextended SO
radius, not inside `Rvir`); and any pre-merge executable fed a `BDM.config`
containing the new key (which `gen_inputs.py` now always writes) stops at the
first catalogue step after the full compute to that redshift.

Merge recommendation: **not ready** until R1-B1 is fixed (one-line format
change plus a regression test); R1-M1 and R1-M2 should be fixed in the same
pass (text changes in `WriteCatalogueMeta`, and either start-up validation of
`BDM.config` or omitting the default key from generated inputs).

## 3. Verified OK

Record layout (`PMP2linker.f90:696-705`):
- The `write(CatUnitBin)` item list is the 24 values of the text write in the same order: `x,y,z` | `VxMaxx,VyMaxx,VzMaxx` | `Mvir,Mtotal` | `rr` | `Vrms` | `VmaxM` | `int(iHalo,4)` | `Cvir` | `aNpart` | `0_4` | `Xoff` | `VirRat` | `LambdaM` | `1.e3*RadRms` | `Axba,Axca` | `Xax,Yax,Zax`.
- Every item is 4 bytes: locals `x,y,z,Vrms,rr,Cvir,aNpart,VirRat` are declared `real*4` (`:634`); the arrays are `Real*4` in module `Structures` (`:103-109`); `1.e3*RadRms(ip)` is real(4) because the makefile has no `-r8`/`-real-size` (`makefile:6`); `int(iHalo,4)` and `0_4` are integer(4) regardless of `-i8` (not used). No derived types, no real*8, no integer*8 in the list.
- `access='stream', form='unformatted'`: no record markers; 24 x 4 = 96 bytes per row, matching `record_bytes = 96`, `rows = Nhalo` and the test's `size == 96*rows` check.
- `convert='little_endian'` on the OPEN overrides the global `-convert big_endian`, as for the fR_halo (unit 31) and lens-plane (unit 29) stream writers in `PMP2mod_extras.f90`, which the pilots validated; case12 compares all 24 binary columns to the text through glamio's `<f4`/`<i4` dtype.
- `columns`, `dtypes` (`i4` at positions 12 and 15) and `units` lines have 24 entries each and agree with the item list and with `glamio.CATALOGUE_DTYPE` (field order, names, kinds, itemsize 96).

Parser (`PMP2linker.f90:261-393`):
- Keys are lowercased before the `select case`, so `CatalogueFormat`, `catalogformat`, `catalogue_format` match; the value is lowercased, so `Both`/`BINARY` are accepted.
- `io=0` reset is necessary and present: `io` still holds `iostat_eor` from the non-advancing line read, and the generic `if (io /= 0)` after the select would otherwise fire.
- Length guard (`len_trim(value) > 8`) and membership check both raise `CatalogueFormat must be text, binary or both`, the string `asserts.py:72` requires; the harness merges stderr into `main.log` (`run_tests.sh:117`, `> main.log 2>&1`), so `error_unit` output is visible to the test. The `hdf5` value of case4g takes the membership branch.
- The "one scalar value" guard (`scan(trim(value),' '//achar(9)//',/')`) cannot reject any accepted value; trailing `! comment` is stripped first.
- `CatalogueFormat='both'` is reset at every `ReadParameters` call (`:273`), `CatText`/`CatBinary` are recomputed at every `BeginCataloguePublication` (`:407-408`), `CatLabelCur` at `:389`; no state leaks between the BDM calls of one run.
- New binary with an old `BDM.config` (no key): default `both`, text output unchanged, `.bin`/`.meta` added. Old binary with the new key: hard stop (R1-M2).
- `ValidateParameters` is otherwise unchanged and still called from both `ReadParameters` and `SetParameters`.

Staged publication (`:395-503`):
- `CatPubN` is zeroed in `BeginCataloguePublication` and `PublishCatalogue`; `CatPubUnit/Final/Staged` are cleared after publication; `CataloguePublicationPending` is set only after all files are staged and cleared only after all renames, so the `already pending` / `was not started` / `writer requires staged publication` guards are consistent across repeated BDM calls.
- `close(unit,iostat=io)` precedes each `STATUS=NEW` open; closing an unconnected unit returns `io = 0`.
- Staging order text, bin, meta and the same rename order; all units are closed (flushed) before the first rename, so a failed close publishes nothing and a failed `.bin` rename stops before the `.meta` rename. No path writes a `.meta` without a `.bin`: both are gated by the same `CatBinary` in `BeginCataloguePublication`, `WriteFiles` and `WriteCatalogueMeta`.
- The `inquire(file=...,opened=,number=)` check compares against `CatPubUnit(i)`, so a unit swapped by other code would be detected.
- Units 12/32/33: no other `open/close/write/read/inquire` of these units exists in any object of the `PMP2main` link (`makefile:35`); `newunit=` units (negative) used for `BDM.config` cannot collide; unit 13 (`outputB`), 29/30/31 (extras) are distinct. The `open(12,...)` hits are in the standalone tools `PMP2correlation.f90` and `PMP2catalogCorrect.f90` and in an archived copy under `BDM-refine/`.
- Text off (`CatalogueFormat = binary`): unit 12 is never opened; the header loop is skipped by `If(kf==1.and..not.CatText) cycle` (`:2056`, the only iteration of `Do kf=1,1`); `WriteFiles` guards the text write with `if(CatText)`; the `close(12)` at `:226` is a no-op; nothing else writes to unit 12 during `BDM`.
- Path lengths: base path 28 characters in production; `+5` is the length of `.meta`, the longest suffix; the staged-path check uses `len(CatPubStaged(1)) = 256`; the `error stop 'BDM stages too many catalogue files'` is unreachable with at most three files.
- Directory check and empty-path check moved from `BeginCataloguePublication` (text file) to the base path; equivalent to before.
- `Nmaxima == 0` path (`:163-167`): `WriteFiles` is still called, so an empty catalogue is published (header-only `.DAT`, 0-byte `.bin`, `.meta` with `rows = 0`) and `CataloguePublicationPending` is cleared before the next BDM call. `MassMin` adjustment, `MassOne` and `Ovdens` are set (SetParameters ran).

- Called after the row loop (`rows = Nhalo` final) and after `MassMin=max(MassMin,20.*MassOne)` (`:640`), so `MassMin` is the applied threshold; the text "rows also need Npart >= 20" matches `if(aNpart<20.)cycle` (`:681`).

Identical to `PMP2mod_extras.f90:533` (`a_v = AEXPN - ASTEP/2.`) used by the momentum dumps and lens-plane sidecars.
- `velocity_scale = 1/a` text matches `RescaleCoords` (`Vscale=100.d0*Xscale/dble(AEXPN)`, `Xscale=Box/NGRID`); the catalogue velocities are the bulk mean of the rescaled bound-particle velocities (`GetHalo:1211`).

## 4. Open questions for the author

6. The `.meta` free-text values (`a_v`, `MassMin`, `overdensity`, `particle_mass`, `iVirial`, `buffer_width`) carry trailing parenthetical comments while others do not; glamio takes the first token. Is "first whitespace-separated token" the documented contract for all numeric keys, so other readers (halocat) can rely on it?
