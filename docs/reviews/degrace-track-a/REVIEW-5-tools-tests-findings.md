# REVIEW 5: Python tools and the test suites — findings

Branch `degrace-track-a` (merge base 69c9261, 15 commits), read-only review of
`DEGRACE-companion/{gen_inputs.py,check_run.py,compare_ecosmog_pk.py,README.md}`,
`test/precise_z/{run_tests.sh,asserts.py,README.md}`,
`test/extras/{test_modes.f90,check_modes.py,run_modes_test.sh,check_frhalo.py}`,
against PMP2init.f90 (parser), PMP2mod_extras.f90 / PMP2mod_subsample.f90 /
PMP2mod_power.f90 / PMP2mod_density.f90 / PMP2linker.f90 (writers) and
`docs/degrace_ecosmog/`. No tests were run; arithmetic was checked with small
single-threaded Python snippets (parser emulation on a generated `Init.dat`,
epoch-tolerance sweep over all 96 `aout.json` lists).

## 1. Summary

`gen_inputs.py` produces inputs that GLAM parses exactly as intended (every
value line was checked against the fixed-width `i10`/`g12.5` reader after the
last `=`; PkTable header yields h; 17 primaries in all 96 nodes; epochs within
1e-7 of the pinned lists). The precise_z suite's new cases 9–12 and the
extras unit tests do test what the README claims, with two gaps: no test is
sensitive to the axis order / sign / conjugation of the *production* mode
dumps (only binned power is compared), and case12 can pass with zero haloes.
`compare_ecosmog_pk.py` silently drops 259 of the 4032 ECOSMOG epochs (2 of
42 for node 2) because it matches the `f8.5`-rounded header epoch with a
2e-5 relative tolerance. `check_run.py` hard-codes the 17+25 class split,
which the decided production configuration (extras at all 42 outputs) will
fail. Recommendation: **ready after the listed fixes** (M1 is a one-line
tolerance change; M2 is ~15 lines added to the existing V6 block).
