# REVIEW 2: scheduler, parameter plumbing, build, legacy bit-identity

Branch `degrace-track-a` vs `cz` (merge base 69c9261). Scope: PMP2main.f90,
PMP2init.f90, PMP2mod_tools.f90 (globals + ReadSetup block), the hooks in
PMP2mod_analyze.f90, PMP2mod_power.f90 and PMP2linker.f90, and the makefile.
Read-only review; nothing was built or run. Line numbers refer to the branch
head (e7bbc8a). "Pilot" = DEGRACE-companion/runs/Node_002_LCDM_L1024Np1024Ng2048
(binaries from b774f8d, job 12180082), read on disk.

## 1. Summary

The scheduler and parameter plumbing are sound: per-output classes follow the
exact-z permutation correctly, the schedule (and hence `Nclass`) is rebuilt
deterministically on restart, and with the new block absent or all-default the
code path is the same as `cz` except for one new file (`OutputSchedule.dat`),
one console line and ten extra lines in a freshly generated `Setup.dat`;
catalogue, snapshot and checkpoint writers are untouched. Two Major issues:
the new optional-line parsers in PMP2init silently substitute the default when
a line is present but unparseable (legacy `ParseLine` crashes loudly in the
same cases), and `fR at halos` is only tied to `MG_flag`, not to `MG_model`, so
a DGP/symmetron/k-mouflage/csf run can write a meaningless `fR_halo` product.
Both fixes are a few lines. The clean-build order problem of the makefile is
pre-existing and is sidestepped by the author's build sequence.

Merge recommendation: **ready after the listed fixes** (M1, M2; m1-m3 strongly
recommended at the same time, the rest at leisure).

## 3. Verified OK

Legacy identity (flags absent or all default, positive `#outputs`, and `#outputs < 0` with no classes):
- `Nclasses = 0`, `zclass(:) = 1` -> `Nclass(jm) = 1` in the legacy marker (PMP2main.f90:207-212) and `Nclass = zclass(iord(i)) = 1` in SetExactSteps -> `OutClass = max(1,Nclass(ISTEP)) = 1` at every output (82). The BDM guard `iBDM==1 .and. OutClass==1` (PMP2mod_analyze.f90:202) therefore reduces to `iBDM==1`.
- `LensSlab = 0` -> the LensPlanes block (48-54) and its DENSIT are skipped; no extra DENSIT call; `mDENSIT` protocol unchanged. `iExtra = 0` -> ExtraModes, WriteSubsample, the POWERfft5 hook (PMP2mod_power.f90:342) and `fRHaloOpen` (PMP2linker.f90:209) are skipped; `fRHaloClose(Nhalo)` returns at once while `fRHaloActive` is false (PMP2mod_extras.f90:636).
- The only new side effects are `OutputSchedule.dat` in the run directory (unit 29, `status='unknown'`, closed before the main loop; units open at that time are 17 and the already-closed 11), the console line "OutputSchedule.dat written", and ten trailing lines in a Setup.dat produced by the new PMP2init. A Setup.dat from `cz` ends at `csf_beta`; `read(11,'(a)',iostat=ierr)` hits EOF and the block is skipped (PMP2mod_tools.f90:240-241). A `cz` binary reading a new Setup.dat stops after `csf_beta` and ignores the block. The pilot's 4-line block (bin/git_hash.txt = b774f8d) is read by the branch head as `iExtra = 0` etc. via the EOF reset.
- No change to the legacy catalogue or snapshots: PMP2linker.f90 changes are the `use` line and three hook lines; the `write(12,...)` row (634-637), `Nhalo = iHalo` and `PublishCatalogue` are unchanged; PMP2mod_tools.f90 changes are globals + ReadSetup only (`WriteDataPM`/`ReadDataPM` untouched); PMP2mod_density.f90 and the MG solvers are not in the diff. FFLAGS/LDFLAGS unchanged, so the floating-point code generation of existing routines is unaffected.
- Legacy schedule arithmetic (`da`, `a` loop, 1.5x growth, nearest-step choice) is unchanged; the refactor to `jm` preserves exactly the same `Nlist` marking.

Exact-z scheduler and classes:
- `iord` is initialised 1..Nexact and carried through every shift of the insertion sort (PMP2main.f90:274-290); `Nclass(jnear) = zclass(iord(i))` in the moved branch (326) and `Nclass(j) = zclass(iord(i))` in the inserted branch (348); the insertion shift copies `Nclass(k+1) = Nclass(k)` alongside `Alist/dAlist/Nlist/MarkX` (335). `zclass(i)` and `zout(i)` share the Init.dat/Setup.dat order (`zexact(1:Nout) = zout(1:Nout)`).
- Duplicate targets -> Stop (295-301); `z >= z_init` -> Stop (267-271); `z < 0` -> Stop; class count /= output count -> Stop in PMP2init (548-551) and ReadSetup (245); `Nclasses` in 0..1000 enforced in ReadSetup (243). `NlastX` logic is not touched by the branch.
- Restart: `Initialize` runs at every start and rebuilds `Alist/Nlist/MarkX/Nclass` from Setup.dat alone (AEXPN0, ASTEP0, zout, zclass); the exact-z restart check (391-404) is unchanged; `OutputSchedule.dat` is rewritten identically (sequential write + close truncates).
- Nearest-step mode with two `zout` on one step: `min(Nclass, zclass)` makes the fuller class win (208-212).

Epochs and units at the hooks:
- At Analysis time `ASTEP` is the step just taken in both modes (exact-z: `ASTEP = danew` before MOVE, 55-59; legacy: `ASTEP = 1.5*ASTEP` before MOVE, 60-63; ADDTIME adds/sets `AEXPN` after). Hence `a_v = AEXPN - ASTEP/2` (PMP2mod_power.f90:343, PMP2mod_extras.f90:531) is the leapfrog velocity epoch and `a_x = AEXPN` the position epoch, both recorded in the .meta (402-403). `fRHaloOpen`'s `a_old = AEXPN - ASTEP` (568) is the epoch at which `scalar_field` was solved (main loop line 47, before MOVE).
- `fRHaloRow(x,y,z,Rvir(ip))` receives `xMaxx` etc., which are built as `modulo(..., Box)` in Mpc/h in [0,Box) (PMP2linker.f90:1408-1411), matching fRHaloRow's expectation (PMP2mod_extras.f90:580,585); the call sits inside the same loop iteration as the catalogue `write(12,...)`, after the `cycle` filters, so row order and count match; `Nhalo = iHalo` is set before `fRHaloClose(Nhalo)`.
- POWERfft5 hook: placed at the serial point after the three 1-D passes and the sqrt(2) scaling (325-339) and before the squaring (346-352); `iPol==0 .and. iSwitch==0 .and. iPowerRSD==0` fires only from `GetPower(0)` on the full NGRID `FI` (48) and never from `GetPower(1)`'s NGRID/2 passes (84-91); `ExtraModes(..., merge(1,0,iPower==1 .and. iPowerRSD==0))` is the same condition, so density modes are dumped exactly once per class-1 output. `MomentumDeposit` and `WriteSubsample` do not reference `FI`/`mDENSIT`.
- Analysis hook order: LensPlanes first, on a fresh DENSIT, before anything overwrites `FI` (48-54); later consumers see `mDENSIT = 0` and skip their own DENSIT; ExtraModes/WriteSubsample run after P(k) and before `iDumpPart`/`iBias`/BDM, which modify `FI` or the particle buffers.

PMP2init / Init.dat / Setup.dat formats:
- Template lines (646-654) have the `=` at column 27 followed by one space and a 9-wide field, i.e. exactly the `i10`/`g12.5` windows of the parser; gen_inputs.py uses the same widths (`{:9d}`, `{:9.3f}`); none of the new comments contains `=`. `Nout` is made positive (486) before the `Nclasses /= Nout` test; the class list is read list-directed so it may span lines (the generator writes 20 per line, PMP2init writes `(50i3)`).
- The Setup.dat block is read with list-directed reads, so the `=` in its comments ("(0 = all class 1)", "(0 = off)") and the `/` in "[h/Mpc]" are never reached (the input list is satisfied by the first token). The header line (`write(10,*)`, leading blank) fits `Line*80` and matches `index(Line,'extra outputs')`.
- `'(a,/,(10f10.5))'` is correct for 1..1000 values (format reversion to the last parenthesised group, one record per 10 values). The pilot's init.log, produced by the pre-fix b774f8d binary, shows the garbage bytes the old `'(a,10f10.5)'` emitted after the first ten values, confirming the fix was needed.
- Validation present and correct: classes in {1,2}; `LensSlab`, `LensGrid` non-negative, divide `Ngrid`, `LensGrid <= Ngrid`; `iExtra` in {0,1}; `kc > 0`; `NdepMom` in [8, Ngrid] after resolving 0 -> Ngrid/2; `int(kc*Box/2pi) <= N/2-1` for both grids (same formula as DumpModes to within real*4 rounding; DumpModes clamps anyway, 354-358); `SubM >= 0`; `FRhalo` in {0,1}.

Makefile:
- `OBJ` order satisfies the new module chain Tools -> fft5 -> Density -> ExtraOutputs -> Subsample (+ glam_hash.o) -> Power -> LinkerList -> Analyze; `PMP2start`'s link list (86) adds `PMP2mod_extras.o` after Density and before Power, which is what Power's `use ExtraOutputs, only: DumpModes` needs; `PMP2linker.o`'s explicit rule now lists `PMP2mod_extras.o`; `glam_hash.o` has its own rule and is covered by `clean`. `CC = icx`, `CFLAGS = -O2 -g -march=core-avx2 -mcmodel=medium` are valid for icx on Zen 2 (no `-x*`), and linking a C object with `ifx` needs nothing extra. `ic2pm`/`gadget2pm` (Tools only) are unaffected.

## 4. Open questions for the author

1. Restart never replays an output step: the checkpoint (PMP2main.f90:73-77) precedes Analysis (79-86) in the same iteration and a restart resumes at ISTEP+1. A job that dies inside Analysis at a step that is also a checkpoint leaves partial `LensPlanes/deltam/mom_*/Subsample/fR_halo` files that are never regenerated (pre-existing behaviour, now with more products). Is check_run.py meant to catch this (sizes against .meta), or should the writers use a temporary name and rename on completion?
2. The plan records the decision "extras at all 42 outputs (every output is class 1)" (section 9, 2026-10-17), while the README example and the pilot use `--classes primary` (17 class-1 + 25 class-2). The code implements the mechanism correctly either way; please confirm which class list the production campaign will use so that Review 5/6 can check the generator default.
3. Is the nearest-step mode (positive `#outputs`) with a class list a supported combination? It works (classes attach to the nearest step, fuller class wins on collisions) but is not mentioned in the README.
4. `PMP2mainMPI.f90` was not updated (own `LocalData`, no `Nclass`, no `OutputSchedule.dat`). Intentional (unmaintained driver)? If so, a one-line note in the plan would prevent someone from using it with a class list.
