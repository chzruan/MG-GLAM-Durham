## 1. Summary

The dump is index-exact and convention-exact against both FML and GLAM: the
Gaussian field is drawn directly in Fourier space with <|delta_k|^2> = P/L^3
and FML's unnormalised c2r, which is the stated delta_k = N^-3 sum_x delta(x)
exp(-i k.x); the local index, the kx mapping, the Hermitian iz = 0 plane, the
clamp, the chunked exact MPI_Reduce and the C(0:n,-n:n,-n:n) layout all match
GLAM's `DumpModes`, and the growth factor is GLAM's `GrowthRaw` line by line
(Simpson vs adaptive quadrature agrees to 2e-11, not merely 1e-6). The
`llround` ID hunk is provably correct and changes nothing for Np = 2048. The
Python checks have the right signs and header offsets and would catch a
transposition, conjugation, cell shift or wrong D. What is missing is
operational robustness: D_gen is tied to the Lua cosmology and nothing checks
it against the P(k) table or the GLAM run (a 0.7 % silent bias for Om 0.3 vs
0.3089 passes V3's 1 % tolerance, which is itself looser than the plan's V3
criterion), the test depends on two untracked input files and never rebuilds a
stale binary, an open failure on rank 0 deadlocks instead of aborting, and the
production Lua would rewrite the existing 2048^3 IC if rerun to obtain the dump.
**Recommendation: ready after the listed Minor fixes** (R4-1 to R4-7); no
Blocker or Major.

## 3. Verified OK

- **Fourier convention of the dumped field.** `generate_gaussian_random_field_fourier<3>` (`GaussianRandomField.h:296-436`) sets `delta_k = sqrt(-ln u * P(k)/V) e^{i phi}` directly on the half-complex grid (no r2c, no filter, no cell-centre shift, no growth factor; `Pofk_of_kBox_over_volume` is `P(2 pi |m|/L)/L^3` from the table at z_ini, `Main.cpp:202-206`). FML's c2r is unnormalised (`FFTWGrid.h:947-996`, no `norm`) and its r2c divides by N^3 (`FFTWGrid.h:922`), so the real-space field is `delta(x) = sum_k delta_k e^{+ik.x}` and `delta_k = N^-3 sum_x delta(x) e^{-ik.x}` with `P(k) = L^3 <|delta_k|^2>`, as the meta states. `fix_amplitude` acts inside the generator and `ic_reverse_phases` (`Main.cpp:233-252`) runs before the dump (`Main.cpp:257`), both recorded in the meta.
- **Index mapping.** `(ixl*Nmesh + iy)*(Nmesh/2+1) + iz` equals `FFTWGrid::get_index_fourier` (`FFTWGrid.h:870`); `get_fourier_from_index` and the generator's `get_fourier_grid()` apply the same left-extra-slice offset (`:1033`, `:465`), so the `nextra` slices of `delta` are handled consistently; half-complex axis is the last (`NmeshPerDimFourier[N-1] = Nmesh/2+1`, `:750`); `kx = ix <= N/2 ? ix : ix-N` equals FML's `get_fourier_integer_wavevector_from_index` (`:1227`) and the generator's own `kvec[0]` (`GaussianRandomField.h:387`); `ix = Local_x_start + ixl` with FFTW-MPI slabs along x and no transposed output.
- **Hermitian iz = 0 plane and Nyquist.** The generator fills `(i,j,0)` and `(N-i, N-j, 0) = conj` for `0 < i < N/2`, and `(0,j,0)`/`(0,N-j,0)` for `j < N/2` (`GaussianRandomField.h:379-431`); planes with any index `= N/2` are left zero; the dump keeps both halves, `n <= N/2-1` excludes the Nyquist index, and `k = 0` is zeroed on task 0 after the reduce (`DeltaLDump.h:107`). `check_deltaL.py:109` tests `cube[::-1, ::-1, 0] == conj(cube[:, :, 0])` with the right index reflection.
- **MPI.** `FFTWGrid` asserts `Nmesh % NTasks == 0` (`FFTWGrid.h:743`) so every rank owns exactly `Nmesh/NTasks >= 1` slabs and each global `ix` appears on exactly one rank; the float `MPI_SUM` therefore has one non-zero addend per element (`x + 0 + ... = x` exactly), which makes the cube rank-count independent, consistent with the identical-md5 claim. All ranks execute the same chunk loop with identical `cnt`; `1 << 28 = 268,435,456 < INT_MAX`; n = 244 needs one chunk (117,169,290 floats); `MPI_IN_PLACE` is used correctly on the root; `std::complex<float>` is layout-compatible with `float[2]`; ranks without cube modes contribute zeros; non-MPI builds have `ThisTask = 0`.
- **Layout identity with GLAM.** `DumpModes` writes `C(0:nm,-nm:nm,-nm:nm)` as a stream (`PMP2mod_extras.f90:359,375-377`), i.e. iz fastest, then iy, then ix; the generator's `cube[iz + (n+1)*((ky+n) + (2n+1)*(kx+n))]` is the same order; both use `n = int(kc*Box/2pi)` with the same `N/2-1` clamp and the same `layout`/`fourier_norm`/`modes` strings; GLAM's `grid node i at x = (i-1) Box/N` with `ic2pm`'s `x = pos*N/Box + 1` (`ic2pm.f90:254`) is the generator's `grid value j at x = j Box/N`.
- **Growth factor.** `growth_raw` is `GrowthRaw` (`PMP2mod_extras.f90:230-251`) line by line (x0 = ln 1e-8, 4000 Simpson intervals, 1/4/2 weights, prefactor `sqrt(Om/a^3 + OL)`). With `a'H(a') = H0 a'^{-1/2}(Om + OL a'^3)^{1/2}` and `da' = a' dx`, `int_0^a da'/(a'H)^3 = int e^{2.5x}/(Om + OL e^{3x})^{1.5} dx / H0^3`, so `growth_raw ∝ E(a) int_0^a da'/(a'E)^3 = D(a)` (Heath). Numerically (Python, scipy `quad` of the da' form at `epsrel 1e-12`): relative difference 1.7e-11 at a = 1/50 for Om = 0.25, 0.3, 0.3089, 0.35; lower-limit truncation 2e-16; the meta's `D_gen(a_ini) = 0.02567447947` (Om = 0.3) is reproduced. Omitted: radiation, massive neutrinos, curvature (documented as flat matter+Lambda; because GLAM uses the identical formula, `deltam/delta_L = D_code(a)` holds regardless, see Open question 5).
- **Lattice statement and ID hunk.** `create_particle_grid` places `Pos[idim] = coord[idim]/double(Npart_1D)` (`MPIParticles.h:554`), so q = i L/Np with no half-cell offset, stored as `double` (`SimpleParticle.h:75-77`), and `Main.cpp:321` copies pos to q before any displacement. `ID = 1 + ix + Np(iy + Np iz)` (`Main.cpp:371`) matches the meta. For q = i/Np, `|q*Np - i|` is a few ulp, so `llround` returns i for every i and every Np; `q*Np = Np - 0.5` would need `q = (Np-0.5)/Np`, not a lattice value, and the clamp is then inert; `floor` is wrong whenever `(i/Np)*Np` rounds below i (3 of 224 planes in double, 93 of 224 if q were float32; none for Np = 128, 1024, 2048; computed), and whenever `floor` is right `llround` gives the same value, so the hunk never changes a correct ID. For the production Np = 2048 (power of two) both agree, so the already generated IC is unaffected. The hunk touches only the ID (positions/velocities use `displacements_*` only). APPLY.md describes this truthfully apart from the wording in R4-10.
- **axis_map.** Interpolation uses `x[idim] = pos[idim]*Nmesh` per grid axis with `CELLCENTERSHIFTED` undefined anywhere in FML or `Makefile.intel` (`ParticleGridInterpolation.h:538-586`): node convention, a particle on a node takes exactly that node's value. `GadgetWriter` writes `float(pos[idim])*pos_norm` for idim = 0,1,2 in order (`GadgetUtils.h:621-631`). FFTW's slab axis is `coord[0]` = pos[0] = Gadget x, so `ix` is the Gadget/GLAM x axis.
- **Test A's formula and sign.** FML: `phi_1 = delta/k^2` (`DisplacementFields.h:306`), `Psi_j = i k_j phi` (`:223,234`), so `-i k.Psi = delta` for the e^{+ik.x} real-space convention; numpy `fftn` uses e^{-2 pi i jk/N}, matching `delta_k = N^-3 sum_x delta(x) e^{-ik.x}`; negative indices via `K % N`; because Np = Nmesh and the interpolation is node-centred, `Psi(q_i)` is exactly the grid value, so A is exact for 1LPT up to float32 position rounding (tolerances 1e-5 mean, 1e-4 residual, 2e-3 per mode are appropriate).
- **Test B's deposit and window.** Nodes at `(j + 1/2) dx` give `delta_k = F e^{-i pi (mx+my+mz)/N}` (`check_deltaL.py:164` has that sign); `W_CIC = prod sinc^2(pi m_i/N)` (`W1`), with `m = 0` handled; the 'half-cell shift' alternative applies the opposite ramp.
- **Discriminating power.** An x<->y transposition, a conjugation, a global sign, a one-cell or half-cell shift, or a wrong D (including a 1 % radiation-level error) each move the mean ratio by >= 0.7 % (shift: `<cos phi>` over the cube < 1 - 1e-3; wrong D: by the D ratio), caught by A at 1e-5/2e-3 and B at 2e-3; the explicit alternative-hypothesis checks are redundant confirmation. `D_quad` is an independent (da', not d ln a) check of the Simpson formula at 1e-5.
- **Gadget-1 header offsets.** 72 (time), 80 (redshift), 96 (npartTotal), 124 (num_files), 128 (BoxSize), 136/144/152 (Omega0/OmegaLambda/HubbleParam) match `GadgetHeader` (`GadgetUtils.h:74-98`, `static_assert(sizeof == 256)`); record markers `<i`; 8-byte IDs from `-DGADGET_LONG_INT_IDS`.
- **run_deltaL_test.sh.** `fail=1` is set in the main shell in every case (`gen` is a function; the `|| { ...; fail=1; }` groups follow subshell commands but run in the parent); the Python exit codes propagate through `|| fail=1`; `module` is an exported shell function in this environment, so `module load` works in a `#!/bin/bash` script; the `awk`/`sed` patterns match `Init.base.dat` lines 1-3, 6, 8-9, 25 exactly; `ic2pm` gets the explicit `half` argument per AGENTS.md; 40 steps from a = 0.02 with da = 6e-4 reach a = 0.044 > 1/31, so both exact outputs (z = 48, 30) occur; appended `Init.dat` lines contain no `=` in comments; `PMcrs*` and the IC particle files are removed, the work tree is gitignored (`.gitignore:91`); resource use (4 ranks x 1 thread, then 1 process x 4 threads, `nice -n 19`, < 1 GB) is within the login-node light tier.
- **Production arithmetic and file names.** n = floor(1.5 x 1024/2pi) = 244; (2n+1)^2(n+1) = 58,584,645 modes; 468,677,160 B = 0.469 GB (0.436 GiB) ✓ "0.47 GB". Smoke test n = 20, 282,408 B, matches the on-disk `IC_test_Np128_L256_deltaL.bin` (282,408 B). `write_deltaL` defaults to `false`, so existing jobs are unchanged unless the Lua is edited. The tracked port copies equal the build-directory copies byte for byte (`Main.cpp`, `DeltaLDump.h`, `Makefile`, `input.lua`, `input_production_L1024_Np2048.lua`).
- **Precision.** `FloatType` is `double` in this build (`FFTWGlobal.h:34`; neither single nor long-double define set), the division by D is done in double and rounded once to float.
